# 阿里云短信开通流程

> 记录日期：2026-08-27
> 状态：**待办（代码已就绪，缺阿里云控制台资质/签名/模板）**

从「开通阿里云短信」到「手机验证码登录正式生效」的完整链路。技术侧 `sms.py` 已实现，配置 4 个环境变量即自动从「打印日志」切到「真实短信」。

## 与代码的对应关系

| 环境变量 | 阿里云控制台对应物 | 说明 |
|---|---|---|
| `ALIYUN_ACCESS_KEY_ID` | AccessKey（建议 RAM 子账号） | 只授 `dysmsapi:SendSms` 最小权限，别用主账号 AK |
| `ALIYUN_ACCESS_KEY_SECRET` | 同上 | |
| `SMS_SIGN_NAME` | 短信签名 | 2~8 字，用个体户名称或产品名 |
| `SMS_TEMPLATE_CODE` | 短信模板 Code | 验证码模板，必须含 `${code}` 变量 |

代码发送的模板参数是 `{"code":"123456"}`（见 `sms.py`），所以模板变量名必须叫 `code`。

## 完整流程（按顺序）

### ① 企业实名认证
用个体户完成**企业实名认证**（个体户算企业认证）。个人认证账号无法申请正式签名、发短信受限。

### ② 开通短信服务
阿里云控制台 → 短信服务 → 开通（按量付费，国内验证码短信约 0.045 元/条）。

### ③ 申请「资质」（约 2 个工作日）
- 填写：单位名称、法人姓名、法人身份证号、证件有效期（长期填 2099-12-31）、经办人手机号。
- 上传：营业执照 + 法人身份证正反面 + 经办人身份证正反面。
- **个体户没有公章 → 用法人签名替代**（官方明确支持）。
- 资质审核通过后才能申请签名和模板。

### ④ 申请「签名」（审核约 2 小时 + 运营商报备 5~7 个工作日）
- 签名名称 2~8 字，选择「自用资质」。
- ⚠️ 签名审核通过后还需**运营商实名报备 5~7 个工作日**（可能更长），报备成功前无法发送。这是整条链路最长的环节，尽早启动。

### ⑤ 申请「模板」（约 2 个工作日）
- 模板类型：验证码。
- 模板内容示例：
  ```
  您的验证码为${code}，5分钟内有效，请勿泄露。
  ```

### ⑥ 创建 AccessKey（RAM 子账号）
- RAM 控制台 → 创建用户 → 勾选「OpenAPI 调用访问」→ 授权策略 `AliyunDysmsFullAccess` 或自定义最小权限 `dysmsapi:SendSms`。
- 保存 AccessKeyId / AccessKeySecret（Secret 只显示一次）。

### ⑦ 填 .env + 部署
在服务器 `/root/video-note/.env` 填 4 个配置项，然后：
```bash
cd /root/video-note && docker compose up -d --build
```
前端发送验证码即走真实短信，不再打印到日志。

## 时间预期

| 步骤 | 耗时 |
|---|---|
| 企业实名认证 | 即时~1 天 |
| 资质审核 | ~2 工作日 |
| 签名审核 | ~2 小时 |
| 运营商实名报备 | 5~7 工作日（可能更长） |
| 模板审核 | ~2 工作日 |

**整体约 1~2 周，瓶颈在运营商实名报备。**

## 已做的防护

- **发送频控**：同手机号 60 秒内不重复发（`sms.py` `SEND_INTERVAL_SECONDS`），防短信费被刷。
- 验证码 5 分钟过期，校验通过即标记已用，防重放。
